# MGTR Dataset Pipeline

Data preparation for **MOA-MGTR: A Mixture-of-Adapters Routing Framework for Clinical Tasks at Multiple Temporal Granularities**.

The pipeline builds medication–laboratory prediction examples from MIMIC-III and prepares the benchmark inputs used for remaining ICU length-of-stay (LOS) prediction. It covers three tasks that use different observation windows and prediction targets.

| Task | Observation window | Prediction target | Main script |
| --- | --- | --- | --- |
| Task 1 · Short-term response | Laboratory measurements within 24 hours before and after prescription start | `POS`, `NEG`, `UNCERTAIN`, or `OPPOSITE` | [`Task1_30pair.py`](scripts/Task1_30pair.py) |
| Task 2 · Medication phenotyping | Up to 14 days from the first prescription start for a drug within an admission | `TOXICITY`, `REBOUND`, `TARGET_ACHIEVED`, or `REFRACTORY` | [`Task2_label.py`](scripts/Task2_label.py) |
| Task 3 · Remaining ICU LOS | ICU time series up to each benchmark prediction point | Remaining ICU stay in hours, with utilities for mapping the target to 10 LOS bins | [`preprocess_LOS.py`](scripts/preprocess_LOS.py) |

## Repository layout

| Path | Contents |
| --- | --- |
| [`scripts/Task1_30pair.py`](scripts/Task1_30pair.py) | Pairs prescriptions with baseline and follow-up measurements and assigns short-term response labels. |
| [`scripts/Task2_label.py`](scripts/Task2_label.py) | Builds trajectories, applies phenotype rules, and serializes full windows or observation prefixes. |
| [`scripts/knowledge_base.json`](scripts/knowledge_base.json) | Task 2 rules for 30 medication categories, including laboratory item IDs, valid ranges, and absolute or baseline-relative thresholds. |
| [`scripts/preprocess_LOS.py`](scripts/preprocess_LOS.py) | Serializes and tokenizes LOS benchmark time series for the train and test partitions. |
| [`scripts/build_los_stay_hadm_map.py`](scripts/build_los_stay_hadm_map.py) | Maps benchmark stay filenames to MIMIC-III admission and ICU stay identifiers. |
| [`scripts/los_structured_utils.py`](scripts/los_structured_utils.py) | Loads structured time series, splits samples by patient, and provides LOS binning and evaluation helpers. |
| [`scripts/analyze_LOS_course.py`](scripts/analyze_LOS_course.py) | Generates prediction summaries and case plots using trained LOS models and their supporting modules. |

## Data access and setup

Tasks 1 and 2 require the uncompressed `PRESCRIPTIONS.csv`, `LABEVENTS.csv`, and `D_LABITEMS.csv` files from MIMIC-III v1.4 in the same local directory. Access is granted to individual researchers through credentialing, training, and a signed data use agreement. [MIMIC-III v1.4 on PhysioNet](https://physionet.org/content/mimiciii/1.4/)

Task 3 starts from the LOS dataset generated by the upstream MIMIC-III benchmark. Follow the upstream extraction, episode construction, and train/test split instructions and run its `create_length_of_stay` step. Keep both the generated LOS tree and the benchmark's intermediate subject-level tree. The LOS preprocessor uses the former, and the stay mapping uses both. [MIMIC-III Benchmarks](https://github.com/YerevaNN/mimic3-benchmarks#building-the-benchmark)

Use Python 3.11 and run the commands below from the repository root. For Tasks 1 and 2, install:

```bash
python -m pip install numpy pandas tqdm
```

For LOS tokenization, also install:

```bash
python -m pip install torch transformers
```

The stay-mapping command uses the Python standard library. The structured LOS utilities additionally import `scikit-learn`, and the course-analysis script uses `matplotlib`.

## Build the datasets

### Task 1 · Short-term drug–laboratory response

Set `BASE_PATH` in `scripts/Task1_30pair.py` to your local MIMIC-III CSV directory, then run:

```bash
python scripts/Task1_30pair.py
```

The script selects the latest matching laboratory measurement in the 24 hours before `STARTDATE` and checks it against the configured valid range. It compares each eligible measurement in the following 24 hours against that baseline, then assigns a class using the expected direction of change and medication-specific thresholds in `EVIDENCE_MAP`. It removes duplicate rows by admission, drug, laboratory name, and time offset.

The output is `task1.csv` in the current working directory. Each row represents one baseline–follow-up pair.

| Fields | Meaning |
| --- | --- |
| `SUBJECT_ID`, `HADM_ID` | Patient and hospital admission identifiers. |
| `DRUG`, `LAB_NAME` | Prescription drug name and laboratory measure. |
| `BASE_VALUE`, `POST_VALUE`, `DELTA_PERC` | Baseline value, follow-up value, and relative percentage change. |
| `TIME_OFFSET_HRS` | Hours from prescription start to the follow-up measurement. |
| `LABEL`, `INPUT_TEXT` | Rule-derived class and English text representation of the paired measurements. |

### Task 2 · Mid-term medication phenotyping

Set the `MIMIC_III_PATH` environment variable and run the generator.

**Bash**

```bash
export MIMIC_III_PATH="/path/to/mimic-iii-clinical-database-1.4"
python scripts/Task2_label.py
```

**PowerShell**

```powershell
$env:MIMIC_III_PATH = 'D:/data/mimic-iii-clinical-database-1.4'
python scripts/Task2_label.py
```

Within each admission, the script groups prescriptions by drug name and takes the earliest `STARTDATE` as the trajectory origin. It collects the configured laboratory measurements over the next 14 days, sorts them by observation time, keeps the last row at duplicate timestamps, and requires at least five valid observations. It assigns labels using the full sequence. Absolute-threshold rules check for toxicity first, then rebound, then target attainment, and assign refractory status to the remaining trajectories. Baseline-relative rules use changes from the initial value.

The script writes `scripts/Task2_all.csv`. To prepare a partial-observation input, set `EARLY_OBS_FRACTION` in the script, for example `0.4`. This changes the prefix represented in `INPUT_TEXT` while preserving the full-window label. The output filename stays the same across fractions, so save each export under a distinct name if you need multiple fractions.

| Fields | Meaning |
| --- | --- |
| `HADM_ID`, `DRUG`, `LAB_NAME` | Admission, prescription drug name, and laboratory measure for the trajectory. |
| `OBS_COUNT`, `WINDOW_DAYS` | Number of valid observations and elapsed days from prescription start to the final observation in the full trajectory. |
| `LABEL`, `INPUT_TEXT` | Full-window phenotype and the serialized full trajectory or observation prefix. |

### Task 3 · Remaining ICU length of stay

Set `MODEL_NAME` in `scripts/preprocess_LOS.py` to your local Bio_ClinicalBERT tokenizer directory. The script loads it with `AutoTokenizer.from_pretrained`. Set `DATA_DIR` to your benchmark LOS directory or use the default layout below. [Bio_ClinicalBERT model card](https://huggingface.co/emilyalsentzer/Bio_ClinicalBERT)

```text
dataset/length-of-stay/
├── train/
│   ├── listfile.csv
│   └── <stay>_timeseries.csv
└── test/
    ├── listfile.csv
    └── <stay>_timeseries.csv
```

```bash
python scripts/preprocess_LOS.py
```

The preprocessor reads `stay`, `period_length`, and `y_true` from each `listfile.csv`. It serializes observations up to `period_length`, tokenizes them to a maximum of 512 tokens, and writes per-example tensors and an `index.pt` for each split under `processed_los/`. Each example includes token IDs, an attention mask, the raw and log-transformed LOS targets, the stay filename, and the observation duration.

To link the LOS samples to admission-level Task 2 trajectories, run the mapping script with the directory containing the benchmark's `train/` and `test/` subject folders:

```bash
python scripts/build_los_stay_hadm_map.py --root-dir "/path/to/benchmark/data/root" --los-dir "./dataset/length-of-stay" --task2-csv "./scripts/Task2_all.csv" --output "./stay_hadm_map.csv"
```

The resulting map contains `stay`, `HADM_ID`, `SUBJECT_ID`, `ICUSTAY_ID`, the episode index, the root partition, and LOS split membership. The optional Task 2 file is used to report admission overlap. The mapping identifies records for linkage. Time-aligned phenotype features are constructed in the model pipeline.

### LOS course analysis

`analyze_LOS_course.py` generates risk and phenotype summaries, trajectory tables, and case plots. It requires compatible LOS checkpoints and the model modules `train_LOS_fusion`, `train_LOS_task2_prior`, `train_LOS_task2_time_aligned_prior`, and `train_LOS_V1` from the model project. These modules and checkpoints are outside this dataset folder. Once those dependencies are available on the Python import path, use `python scripts/analyze_LOS_course.py --help` to inspect the supported checkpoint, prediction CSV, and output options.

## Interpreting the outputs

- The Task 1 and Task 2 CSVs are preprocessing exports. Training and validation splits are applied downstream. Task 1 standalone experiments use a balanced, record-level stratified split, and joint training uses an admission-level split. Task 2 groups by admission and reuses one split across observation fractions.
- Both generators expose an admission cap through `SAMPLE_LIMIT`. Task 1 takes matching admissions in source order. Task 2 uses seed `42` when the number of eligible admissions exceeds the cap.
- The local `sample/` directory contains two five-row CSVs that illustrate the file layout. `task2_sample.csv` uses labels including `FLUCTUATE`, `MONOTONIC_RISE`, and `RISE_FALL`. Use the output of `Task2_label.py` for the four-class phenotype task described here.
- Keep credentialed inputs and derived patient-level exports in your authorized data environment. Use synthetic rows for public examples. PhysioNet provides a credentialed route for sharing derived MIMIC datasets. [PhysioNet guidance on derived datasets](https://physionet.org/news/2024/#guidelines-for-creating-datasets-and-models-from-mimic)
